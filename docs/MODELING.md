# 语义建模与低标注成本的双层情感分析

系统把评论文本、用户评分、主题、预测情绪和互动信息汇入一张知识图谱，再供检索与 Agent 使用。建模层形成可检查的中间产物，服务层复用这些产物，无需每次问答重新分析全量文本。

![完整建模与问答流程](../assets/modeling-pipeline.svg)

## 一次编码服务多个任务

使用 `paraphrase-multilingual-MiniLM-L12-v2`，123,693 条评论各对应一个 384 维向量。这套表示同时用于情绪扩展特征、BERTopic 聚类与在线语义检索，避免各任务重复编码。查询侧使用相同编码器与归一化设置，保持语义空间一致。

## 双层标签分别回答两类问题

| 层次 | 来源与处理 | 输出 | 用途 |
|---|---|---|---|
| 评分态度 Sentiment | 1–2 星为负面，3 星为中性，4–5 星为正面 | 3 类显式态度 | 样本内星级倾向统计 |
| 文本情绪 Emotion | mDeBERTa NLI 零样本伪标注，再由 LightGBM 扩展 | 喜爱、感动、惊喜、中性、失望、愤怒、厌恶 | 情绪分布、两层不一致线索与观点检索 |

### 从 10,000 条伪标注扩展到 123,693 条评论

1. 抽取 10,000 条评论，用 `mDeBERTa-v3-base-mnli-xnli` 将七类情绪转成 NLI 候选假设，取对应预测标签。
2. 将 384 维 SBERT 向量、Star 评分、文本长度拼成 386 维特征，训练 LightGBM 多分类扩展器。
3. 对全量评论预测，保留预测置信度，并与评分态度计算一致性标记。

这一方法减少对全量人工标注与全量 NLI 推理的依赖，LightGBM 可在 CPU 上承担批量扩展。设计中比较了 LightGBM 基线、类别平衡、大容量配置、随机森林，以及移除星级/仅保留嵌入的特征消融。

评分层记录用户的显式评价，情绪层记录文本模型的预测，两者共同支持分布分析与样本核查。扩展器将星级作为一个特征；入图时保留标签来源和置信度，便于追溯每个预测及后续更新模型。

## BERTopic 主题发现与人工命名

| 环节 | 配置或处理 |
|---|---|
| 语义输入 | 共享的 384 维 SBERT 向量 |
| 降维与聚类 | UMAP `n_components=5`；HDBSCAN `min_cluster_size=80` |
| 中文表示 | jieba 分词、停用词与主题关键词提取 |
| 噪声与合并 | 基于嵌入余弦的噪声重分配、人工合并为 18 个主题 |
| 解释与显示 | 结合关键词和代表评论核验命名；服务保留稳定 ID、关键词和显示别名 |

柱状图对应公开的[主题汇总 JSON](../results/modeling/summary.json)，18 个计数合计 123,693；不包含评论原文或用户标识。主题名称概括评论聚类，不是电影题材标签，也不能代替正面/负面条件。

![主题嵌入t-SNE投影](../assets/topic-clusters.png)

颜色区分主题，二维投影展示评论在语义空间中的分布。主题表示结合句子语义与可阅读关键词；人工别名提供统一的查询入口，稳定 ID 保持图谱关系与历史引用一致。

### 主题表示的选择

采用句子嵌入聚类，以覆盖用词不同但含义相近的短文本；以 LDA 作为词袋基线核验主题表示。主题建模与在线检索共享编码结果，主题关键词与代表评论共同支持语义核验。

## 模型产物如何进入问答

每条评论保存主题、评分态度、预测情绪、置信度和时间等信息，并建立五类图关系。图谱查询可按这些维度交叉聚合；向量检索在相同条件内寻找相近表达；Agent 调用受限工具获取统计或评论证据。模型预测来源随数据保留，避免把预测情绪写成用户自己声明的情绪。

本仓库提供服务、工具、导入与评测代码。离线模型产物通过 CSV 和向量文件接入，原始语料、训练日志及大型产物不随仓库提供。[数据接口](DATA_FORMAT.md) · [图谱与系统设计](PROJECT_DESIGN.md) · [建模汇总 JSON](../results/modeling/summary.json)
