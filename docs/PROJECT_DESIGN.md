# 知识图谱与问答系统设计

系统将评论理解、知识组织、检索与工具执行贯通：建模层生成主题与双层标签，知识层保留评论粒度的关系，服务层把自然语言需求转成可核对的查询和证据。

## 评论粒度的多维信息融合

![六类实体和五类关系](../assets/graph-schema.svg)

| 实体 | 数量 | 建模目的 |
|---|---:|---|
| Movie | 156 | 跨电影聚合与对比 |
| Comment | 123,693 | 保存文本、星级、日期、获赞及分析结果 |
| Topic | 18 | 组织讨论维度、主题分布与相似性 |
| Sentiment | 3 | 保留由评分生成的显式态度 |
| Emotion | 7 | 保留模型预测的细粒度情绪 |
| User | 52,773 | 保存评论发布关联，支持样本内互动分析 |

以 Comment 为中枢，五类关系分别为 `User-POSTED→Comment`、`Comment-REVIEWS→Movie`、`Comment-BELONGS_TO→Topic`、`Comment-HAS_SENTIMENT→Sentiment`、`Comment-HAS_EMOTION→Emotion`。总计 176,650 个节点、618,436 条关系；29 条评论缺少用户关联，其余四类关系覆盖全部评论。

这种粒度允许在聚合统计后下钻到具体评论，保留预测置信度、双层一致性和获赞权重。评分态度与文本情绪分别建模，避免把不同来源的信号压成一个标签。

## 八类分析场景与路径

| 分析场景 | 实现思路 | 依据与边界 |
|---|---|---|
| 电影相似性 | 每部电影形成 18 维主题比例向量，计算余弦 | 反映样本评论的讨论结构，不是电影内容或题材相同 |
| 争议话题识别 | 电影 × 主题 × Sentiment 交叉聚合，再定位代表评论 | 展示样本内不同态度，不外推平台总体口碑 |
| 隐性负面线索 | 中性星级评论中筛选预测为愤怒/厌恶的记录 | 提供待核查线索，不是经验证的未来口碑预测 |
| 双层一致性分析 | 对比评分态度与预测情绪，定位不一致记录 | 保留模型误判与复杂表达两种可能 |
| 情绪与获赞关联 | 按预测情绪计算获赞聚合 | 描述关联，不声称情绪导致传播 |
| 指定片单情绪对比 | 明确人工选择的电影集合，再统计情绪构成 | 没有独立题材标签时，不自动拼接题材全集 |
| 用户互动分析 | 沿 User → Comment 统计发布与获赞 | 范围为当前样本，不推断平台全量影响力 |
| 时间维度趋势 | 按电影和评论日期分组统计 | 历史样本内趋势，不是实时舆情监控 |

## 将分析路径接入大模型

例如“某电影在剧情叙事主题下的负面评价集中在哪里”：

1. 确定电影与主题 ID，并展示当前生效条件。
2. 经 `Movie ← Comment → Topic` 定位评论范围，通过 Sentiment 关系聚合样本数量和分布。
3. 沿相同范围寻找代表评论，引用真实证据 ID。
4. 返回查询、统计行、关联子图与解释，支持从概括回到依据。

这里的可解释路径是可执行的查询与数据关系，模型内部推理过程不作为事实证据。[建模方法](MODELING.md)

## 统计与语义互补

图谱路径负责数量、比例、排名和关联计算；向量路径检索同义表达与具体观点；融合保留图谱聚合行，并对两路评论按 ID 去重后使用等权 RRF（k=60）。聚合行不参与评论排名，避免用少量近邻推断总体。

无筛选时使用 Neo4j 原生向量索引；有筛选时在候选范围内计算余弦排序，减少先取全局少量近邻再过滤的漏召回。统计实验使用强制路径时不跨路兜底。

## Agent、会话与服务执行

![在线服务架构](../assets/architecture.svg)

Agent 以模型决策、工具执行、结果观察的循环调用六个工具：电影概览、情绪统计、主题目录、按主题找电影、评分排名、语义评论搜索。Pydantic 校验参数，未知工具与非法参数返回结构化错误；模型最多响应五轮、工具最多执行十次。

直接问答的会话层分别维护固定条件、近期原文、滚动摘要与上轮真实结果映射。明确条件、修改和撤销由代码维护，摘要不能改变固定条件，“第二条”指向会话中真实返回的证据。

生成查询逐次执行静态只读检查、范围检查、LIMIT 与 EXPLAIN，最多两次重写，并设置查询与请求时限。READ 路由本身不构成数据库权限隔离。接口通过 FastAPI/SSE 返回进度、证据与真实生成片段，界面通过 API 使用服务；Compose 负责初始化与运行，MCP 复用工具，可选 Redis 提供缓存和限流。
